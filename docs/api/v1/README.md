# HomePod Flow 核心接口 v1 冻结基线

冻结日期：2026-11-05。App 和跨语言调用方以 [bridge.h](bridge.h) 的 C ABI v1 为依赖边界；[core.hpp](core.hpp) 仅作为 C++17 源码兼容快照，不保证 STL、虚表或不同编译器的二进制兼容。

[manifest.json](manifest.json) 是机器可读清单，包含原样头文件 SHA-256、9 个导出符号及声明、3 个回调、错误码和行为约束。快照从公共头按字节复制，不是另外设计一套接口。

## 冻结包含什么

除函数名称和参数外，还冻结如下可观察行为：

- float32交错音频；sample_count为跨全部通道样本数，first_frame为每通道帧位置；epoch与连续帧校验不变。
- 统一宿主单调时钟域和共同未来播放计划；成功仅表示后端接受，不等于声学同步。
- 回调样本借用到回调返回；输入不保留；回调/user保持到destroy返回；last_error借用且状态码权威。
- 调用串行，回调不重入、不跨C边界抛异常；不是实时安全接口。
- prepare失败清理所有已尝试输出（含失败者）；输入校验失败不部分enqueue、不推进时间。
- enqueue失败含WouldBlock使全组Faulted，关闭输出、禁止自动重试；不承诺物理原子性。
- stop幂等，清理活动输出及时间线，回Idle；C wrapper保留已配置的输出绑定，可重新prepare。destroy(NULL)安全，destroy完成前回调仍可执行。

错误诊断文字、内部算法、线程内部实现和性能优化可以调整，但不能改变以上外部行为。流式队列/源读取/设备发现等adapter内部功能不属于这9个符号；新增能力不能把原有WouldBlock重新解释成成功，也不能把暂时无数据解释为EOF。

## 兼容策略

v1现有符号、签名、调用约定、错误码值、回调顺序及生命周期不得修改。新能力优先以内部实现或adapter完成。确需新增API，走增量独立符号；破坏性需求另开新版本符号族，并与v1并行保留，建立迁移任务，不得偷偷替换v1含义。

此二进制兼容承诺以相同OS、CPU架构、支持的部署目标及运行库条件为前提，不代表Windows二进制可以放到Mac执行。Python/Swift等不能直接依赖C++ STL接口跨ABI调用。

## 每次改核心的门禁

1. 校验live头及快照与manifest SHA-256一致；检查9个原符号均导出。头一致只是必要条件。
2. 用本冻结头和基线动态库编译/链接一个旧C客户端，保存二进制和hash；后续只替换新动态库，不重编旧客户端，执行既有契约断言并验证实际加载路径。
3. 重跑既有M0/M1行为测试：路由、时间、回调、错误、stop、destroy、背压及清理。再运行新增按块/流式行为测试。
4. 兼容通过只证明旧调用方继续工作；持续出声、协议计划、声学同步和长期稳定分别需要证据。

根协调已保留macOS arm64旧客户端core-api-v1-baseline/flow_bridge_c_tests，SHA-256见manifest；QA负责用旧binary加载新dylib并核对dyld路径。此处记录资产，不预先宣称兼容测试通过。
