# UI_SPEC — 首页 / 设置窗口 / 模式交互

## 视觉锚点与优先级

**P0**：UI 信息层次、布局、入口、状态联动、编辑能力限制正确。  
**P1**：尺寸、字体、间距、背景材质、设备比例、图标、边界、选中态与参照图接近。  
**P2**：装饰性光晕、墙面纹理、家具 3D 质感。可用干净的 SwiftUI 形状代替，不牺牲 P0/P1。

统一风格：浅色、系统半透明材质、较淡描边、蓝色用于开启和选择状态。支持 macOS 深色自适应，但**浅色先还原参考图**。颜色不允许任意引入第三套主题；配色来自 macOS 系统语义色和局部蓝色强调。字体使用系统 SF / 苹方；所有文字必须是 SwiftUI Text，而非烘焙进图片。

## A — 状态栏弹窗（默认）

参考 `01_MENUBAR_REFERENCE.png`；正常显示在顶部状态栏图标下方。建议内容区宽 345~390 pt，根据真实屏幕缩放确认；高度自适应，避免滚动，保持一屏。

从上到下固定：
1. **标题行**：左 HomePod Spatial（小 Logo），下方「空间音频 · 3 台设备已连接」（动态）；右系统样式 `Toggle`。默认选中开启状态的截图仅供视觉参考。
2. **分段控制**：`影院模式 | 同步播放`，左右等宽，单选，蓝色选中背景。无需再设置独立“关闭”选项。
3. **房间布局缩略图**：从设置窗口的**同一份 RoomLayout model 和同一个绘图组件**生成只读小图。电视在上，较大的 HomePod 在前中间；左右两台较小 mini 在后侧；下方头部/左右耳朵朝向电视。设备名称和位置就地标注，确保缩小后仍可辨。影院模式点击缩略图可打开设置窗口并选中空间布局；同步播放模式缩略图仍展示但只能看，不能打开编辑入口（可显示只读提示）。
4. **音量**：喇叭图标、`Slider(0...100)`、当前百分比。启停前后保持用户设置。
5. **音画延迟**：时钟图标、`Slider(-3500...3500)`，右侧可编辑数值（单位建议 ms，也可显示带 3 位小数的秒值）；正负端点提示 ±3.500 s。支持键盘/输入数值精调，值始终限制在范围内；初始 0。
6. **设置…**：底部唯一导航操作，点击后打开独立设置窗口。不要增加退出行或多级菜单占空间（可在标准 App 菜单提供退出）。

小图在首页仅展示当前布局，不是第二个编辑器。若无设备/未授权，以可操作的空态替代假数据，绝不显示“已连接”假状态。

## B — 设置主窗口（唯一的大窗口）

参考 `02_SETTINGS_LAYOUT_REFERENCE.png`。建议约 960×650 pt（允许适配屏幕）；窗口有 macOS 原生标题栏和三色交通灯。主结构：

- **左侧导航栏**（约 160~190 pt）：空间布局（默认且选中）、音频处理、播放偏好、通用设置、关于。轻量，不需要功能复杂化。
- **右侧空间布局内容**：标题「空间布局」+ 提示「配置音箱在房间中的位置（仅影院模式生效）」。主体左侧为大的房间俯视画布，右侧为设备列表与可编辑位置/属性；宽度约 65:35，可按窗口适配。
- **画布**：电视上方，HomePod 前中间，mini 左后和右后，人头（头部俯视 + 两耳）居中接近沙发，设备位置必须来自可拖动的真实数据。可使用 `Canvas`, `GeometryReader`, `DragGesture`, 自绘简化 SVG/矢量素材，禁止整块固定截图充当 Canvas。
- **设备面板**：顶部 `+ 添加设备`；设备为 `名称 + 位置` 两行或一行紧凑展示，选中高亮并同步聚焦画布设备；mini 立体声对在**传输层作为一组两个声道**，画布仍分左右两个空间位置，不能错误拆成两个独立 AirPlay 输出组。
- **听音位置**：位置可拖拽，设备位置按听音朝向转换声道映射；布局操作有明确保存/取消/重置机制（如在底部提供「测试声音」「重置布局」「应用」）。
- **同步播放模式**：布局页仍可看，但编辑控件禁用，并在顶部明确显示「同步播放不使用空间位置」；**不要因此删除或重排默认画布**。
- **设置中其它页**：音频处理（自动处理/低延迟选项仅在能力可用时开放）；播放偏好（记住模式、启动策略）；通用设置（权限、日志入口）；关于（版本、许可证）。页面使用原生表单，禁止将这些项目塞回菜单栏。

### 坐标与听音位置

- 模型使用标准化位置 `(x, y)` 范围 `0...1`，渲染成任意画布尺寸，不能保存屏幕像素。
- 画布相对朝向：顶部为前方（电视侧），底部为后方。左右从听音人的视角解释。
- **默认 Mock 布局**：`front x=.50 y=.29`、`rearLeft x=.20 y=.73`、`rearRight x=.80 y=.73`、`listener x=.50 y=.83`（按画布需要略调整），且所有名称是示例显示文字，不对应真实发现设备。
- 实际外观比例：HomePod 2 高约 168 mm、直径约 142 mm；HomePod mini 高约 84.3 mm、直径约 97.9 mm。俯视图选用直径比约 `1.45:1`，不要直接以高度比渲染俯视图。

## C — 交互／状态矩阵

| 交互 | 影院模式 | 同步播放 |
|---|---|---|
| 输出声道 | 有可映射通道时分配前/后声音；不可分时同声退化 | 相同音频送所有输出组 |
| 缩略图 | 与当前布局实时同步，点击打开编辑 | 显示同一布局，只读 |
| 设置／空间布局 | 可新增、拖拽、保存 | 查看，禁用新增/拖拽/保存 |
| 总音量 | 可调 | 可调 |
| 音画延迟 | ±3500 ms 控件，是否生效取决于后端能力 | 同样 |
| 启停开关 | 当前模式启停音频接管 | 当前模式启停音频接管 |

音画延迟不是**音箱间同步**。音箱间延迟由后端处理；用户只调统一的音画偏移。对于普通系统播放源，若无法对画面进行延迟控制，负偏移不应宣称可以让音频提前超过捕获时刻；明确展示可用能力与限制。

## D — SwiftUI 推荐模块边界

```text
HomePodSpatialApp
 ├── MenuBarExtra / NSStatusItem+NSPopover
 │   └── MenuPopoverView
 │       ├── ModeSegmentedPicker
 │       ├── RoomLayoutThumbnail (read-only)
 │       ├── MasterVolumeSlider
 │       └── AVOffsetControl (-3500...3500)
 └── SettingsWindow (Window, id: "settings")
     └── SettingsSplitView
         ├── SettingsSidebar
         └── RoomLayoutEditor
             ├── RoomCanvas (shared rendering with thumbnail)
             ├── DeviceListInspector
             └── LayoutActions

Observable router/device service -> AppState / LayoutStore -> all views
```

- App 使用单一状态源，模式/布局/启停与设置窗口同步。
- `MenuBarExtra` 如需精确 hover、弹窗高度、布局效果，可使用 `NSStatusItem + NSPopover`，但不能牺牲原生 macOS 行为。
- 不以绘制图片取代可访问的按钮、滑块、Picker、输入框。
- 空间布局使用可维护的矢量/形状或独立授权资源；参考效果图不是授权可复用的 HomePod 3D 素材库。
- UI 适配高 DPI、窗口缩放、浅/深模式、中文与其他系统字体；提供无障碍标签。
