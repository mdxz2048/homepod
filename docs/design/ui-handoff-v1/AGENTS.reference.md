# AGENTS.md — HomePod Spatial UI 实现协议

## 任务
将现有 macOS SwiftUI App 的 UI 高保真还原为 `references/00_APPROVED_FULL_REFERENCE.png`。

## 不可变更的产品决定（优先级最高）
1. 这是**常驻 macOS 菜单栏**应用，用户日常只打开菜单栏弹窗；**没有常驻复杂主控制台**。
2. 菜单栏内容从上到下固定：顶部应用标题/运行开关/状态 → **影院模式 | 同步播放**分段选择 → **真实空间布局缩略图** → **总音量条** → **音画延迟调节（±3500 ms）** → **设置…**。
3. 只有一个启停开关，**不额外加“关闭空间音频”按钮/菜单项**。
4. 「设置…」打开**独立原生 macOS 窗口**（与参照右侧相同）；空间布局为默认页。禁止将设置做成菜单栏里的子页面。
5. 影院模式：取到可独立映射的 2.0 / 5.1 / 7.1 等声道时，按位置路由或按已批准的立体声空间算法处理；如果无法拆分，则所有输出组接收相同内容，不伪称已拆分。
6. 同步播放：不做空间拆分；所有输出组播放相同内容。同步模式下空间布局**只读，不可编辑**；影院模式才允许拖动/保存位置。
7. 音箱标签**仅为实际设备名称 + 位置**，不附加型号介绍、科普文字。参照名称仅为模拟样例，不要硬编码真实设备名。
8. 听音位置必须是**头部俯视图，左右两只耳朵明显可见**；不使用定位图钉或耳机图标替代。
9. HomePod 二代与 HomePod mini 按真实物理比例表现。俯视画布按直径近似比例 142:98≈1.45:1，禁止把 mini 做得与大 HomePod 同大；列表缩略图可作可读性适当放大，主画布保持比例。
10. macOS SwiftUI 原生开发：MenuBarExtra / NSPopover（选择稳定且可调宽高的方案）、Window / NavigationSplitView、Canvas + DragGesture、Picker(.segmented)、Slider、原生按钮和系统材质。**禁止直接把效果图当成 UI 背景图**。
11. 音画延迟 UI 的数学范围为 -3500...+3500 ms，精确到可编辑数值，初始 0 ms；必须准确标示含义。负偏移在无画面控制能力时可能不可实现，显示“不支持/受限”，不可假成功。
12. 异步音频连接状态须由后端事件驱动；UI 的 Demo/Mock 模式必须标明并与真实状态分离。

## 工作顺序
A. 阅读参考图、现有项目结构；提交简短的文件修改计划。
B. 建立 StyleTokens、数据模型、MockRouter，先完成菜单栏弹窗（控制字句、状态、两种模式）。
C. 完成设置独立窗口、房间画布、设备列表、听音位置、拖拽、保存/取消；设置其它页保留必要的真实选项，样式与空间布局一致。
D. 完成影院/同步模式状态联动：同步模式禁止编辑布局，影院恢复编辑。
E. 运行 Xcode build；每个状态截取实际 macOS 运行截图，逐次跟参照图对比并调整。
F. 完成验收表，说明尚未连接的后端功能和真正的系统限制。

## 质量门禁
- 结构、顺序、文案、相对尺寸必须以 `00_APPROVED_FULL_REFERENCE.png` 为第一准则。
- 状态栏默认弹窗不要增加第三个模式、独立关闭按钮或额外面板。
- 不能声称已有多路 AirPlay 2 独立声道、自动同步、捕获 5.1、真实音画同步成功，除非有真实设备测试日志。
- 如有设计歧义，优先选择与参考图**视觉距离最小且 SwiftUI 可维护**的实现，并在说明中列出。
