# 多声道输入/路由 UI 规格 v1（未来态）

**Status: NOT IMPLEMENTED — waiting for L1/L2 gates.**

本文只是未来态设计说明，不是实现批准。当前产品仍是 stereo-only；多声道 HAL/容器（L1）与源/播放器布局报告（L2）均未通过，**不修改任何 app 代码、现有 UI、控件或视觉资源**。

- 只有 L1、L2 通过并获产品书面批准后，才可按本文实现；L3（端点/声学）未通过前，两台 HomePod 永远不显示“原生 5.1/7.1”。
- 本文不新增声道选择器、文件播放器、上混开关、新设置页或新导航项。
- 不提供效果图或 UI mockup；避免把未来态误读为当前可用能力。
- 当前 UI 的立体声行为、文案与布局保持冻结。任何“5.1/7.1 已支持”“影院环绕”字样均不得出现在两台 HomePod 的界面中。

依据：`docs/collaboration/virtual-audio/MULTICHANNEL_CONTRACT.md`（§4–§5、§8）、`MULTICHANNEL_TASK_BRIEF.md`、`docs/collaboration/PRODUCT.md`、`docs/design/ui-handoff-v1/UI_SPEC.md`。视觉语言沿用现有 Apple 风格：系统字体/材质、浅色优先、蓝色强调、单一设置窗口。

## 1. 信息模型（只读展示）

UI 只消费路由/会话层的只读快照，不推断布局，不根据静音或通道数猜声道。

| 字段 | 菜单显示 | 设置显示 | 规则 |
|---|---|---|---|
| `phase` | 状态行 | 状态行 | 见 §4 状态表 |
| `sourceLayout` / `sourceChannels` | `立体声 · 2 声道` | 同左 | 必须带 authority；`player_output` 加“原生性未验证” |
| `sourceAuthority` / `nativeClaim` | 不单独展示 | 高级信息 | 不把 `nativeClaim` 当成整条链路原生 |
| `containerLayout` / `containerChannels` | 不展示 | 容器行 | 只显示已通过 L1 的容器；否则“未验证” |
| `endpointCount` / `endpointSummary` | `端点 2 · 立体声对` | 同左 | 两台 HomePod 只能计为两个 stereo 对 |
| `routeProvenance` / `uiLabel` | 实际路由 | 实际路由 | 必须来自 route plan，不用模板猜 |
| `losses`（downmixed/discarded） | 只在警告行摘要 | 高级信息 | 丢弃 LFE 等必须可见 |
| `warnings` | 最多一条主警告 | 完整列表 | 不以颜色代替文字 |
| `diagnostics` | 不展示 | 折叠区 | 默认收起，只读 |

停止后不得继续显示上次的源布局为当前状态；只能写“未开始”或明确标注“上次”。

## 2. 菜单栏弹窗（未来态）

保留现有 372 pt 宽、材质、间距与顺序；只在“模式”与房间缩略图之间增加一块紧凑的只读“输入与路由”摘要，目标高度 52–64 pt，不引入滚动。

| 顺序 | 区域 | 内容 | 层级 |
|---|---|---|---|
| 1 | 标题行 | `HomePod Flow` + 现有服务状态 + 现有系统声音开关 | 既有 |
| 2 | 模式 | `影院模式 \| 同步播放` | 既有 |
| 3 | 输入摘要 | 第一行：状态点 + 源布局 + 端点徽标；第二行：实际路由 | **新增只读** |
| 4 | 房间缩略图 | 现有布局预览 | 既有 |
| 5 | 音量 | 现有滑杆与百分比 | 既有 |
| 6 | 音画延迟 | 现有控件与不可用说明 | 既有 |
| 7 | 设置… | 唯一导航入口 | 既有 |

输入摘要示例（仅文案结构，不是当前状态）：

```text
● 正在路由   立体声 · 2 声道              [端点 2]
  立体声直通 · 两台 HomePod
```

两台 HomePod 遇到 5.1 源时，只能显示：

```text
● 正在路由   5.1 Side · 6 声道（播放器输出，未验证）   [端点 2]
  5.1 → 两台 HomePod 立体声下混（LFE 丢弃）
```

启停只使用现有右上角开关，不增加第二个 Start/Stop 按钮。开关关闭后摘要变为“已就绪 · 未开始”，不保留旧源声明。

## 3. 设置：唯一“空间布局”页（未来态）

不增加设置页。在右侧检查器顶部、现有“音箱（N）”之前加入只读“输入与路由”卡片；不挤占画布比例，不出现 Picker、滑杆或文件入口。

| 行 | 文案 | 说明 |
|---|---|---|
| 输入 | `立体声 · 2 声道` / `5.1 Side · 6 声道` | `player_output` 追加“（原生性未验证）” |
| 容器 | `HomePod Flow Stereo · 2 声道` | 只显示 L1 已验证容器；否则“容器未验证” |
| 端点 | `2 个 · 立体声对` | 不使用“5.1 端点”描述两台 HomePod |
| 实际路由 | `立体声直通` / `5.1 → 立体声下混（LFE 丢弃）` | 来自 route plan 的 `uiLabel` |

卡片下方保留现有设备、听音位置与布局操作。页面说明追加一句：

> 输入与路由由播放器和当前音箱能力自动决定；此处只读，不在本应用选择声道或文件。

**高级信息**：放在检查器最底部，默认折叠。展开后以 11 pt 等宽次要文字只读显示：容器 UID、源 authority/verified、矩阵 ID/version、损失通道、清理确认。无复制按钮以外的操作，不提供修改入口。

## 4. 组件状态

所有状态都使用“图标 + 文字 + 语义色”，不能只靠颜色。错误状态默认停止整组，不自动循环重试。

| 状态 | 触发 | 菜单主文案 | 视觉 | 操作 | 禁止 |
|---|---|---|---|---|---|
| `unavailable` | 驱动/服务未连接或 UID 不存在 | `输入不可用` | 灰色 `speaker.slash` | 查看设置 | 显示假连接或假源布局 |
| `discovering` | 连接、发现、准备输入 | `正在查找输入…` | 蓝色 `ProgressView`，静态文案 | 无 | 轮播未验证布局 |
| `ready` | 服务就绪、未开始会话 | `已就绪 · 未开始` | 中性圆点 | 现有开关 | 保留旧源为当前声明 |
| `running` | 正在采集与路由 | `正在路由` | 蓝色波形/圆点 | 现有开关关闭 | 仅凭发包称“已出声” |
| `unsupported_layout` | unknown/height/无矩阵 | `无法确认源布局` | 橙色 `questionmark` | 查看详情 | 猜 5.1/7.1，自动上混 |
| `ambiguous_layout` | 5.1 未分 side/back | `5.1 环绕位置未确认` | 橙色 `exclamationmark` | 查看详情 | 默认 side/back；本轮不加手动覆盖 |
| `permission_required` | 缺少音频录制授权 | `需要音频录制权限` | 橙色 `lock` | 打开系统设置 | 绕过 TCC；把静音当权限原因 |
| `device_busy` | 容器有运行中客户端/待配置 | `音频设备正被占用` | 橙色 `hourglass` | 停止后重试 | 杀 coreaudiod；假装已启动 |
| `latency_revision_changed` | `hflr` 意外变化 | `延迟配置已变化，已停止` | 橙色 `clock.badge.exclamationmark` | 重新准备 | 沿用旧 session/校准 |
| `output_restore_failed` | 原输出无法恢复 | `原输出未恢复` | 红色 `exclamationmark.triangle` | 打开声音设置 | 谎称已恢复；静默改默认 |

通用规则：

1. `unsupported_layout`、`ambiguous_layout`、`permission_required`、`device_busy`、`latency_revision_changed` 均不显示“正在路由”。
2. 错误只在状态转换时由 VoiceOver 播报一次；同状态刷新不重复打断。
3. `source_layout_changed` 使会话停止并回到错误/重试态；不得在新布局下沿用旧队列。
4. 任何状态都不能把“两个 stereo 对”画成 6/8 个方向端点。

## 5. 文案与诚实规则

| 场景 | 必须显示 | 禁止显示 |
|---|---|---|
| stereo 进入 5.1/7.1 容器 | `立体声直通（仅前置 L/R，其余静音）` | `5.1` / `7.1` / `原生多声道` |
| 5.1/7.1 源 → 两台 HomePod | `5.1 → 两台 HomePod 立体声下混（LFE 丢弃）` | `5.1 播放` / `原生 5.1` |
| 仅取前两声道 | `仅前置 L/R（其余丢弃）` | `5.1` / `环绕` |
| 播放器报告 5.1 但未验证 | `播放器输出 5.1（原生性未验证）` | `原生 5.1` |
| 5.1 源在 7.1 容器 | `5.1 Side 源在 7.1 容器（多出通道静音）` | `原生 7.1` |
| unknown 受限兜底 | `未知多声道，仅前置 L/R` | `5.1` / `7.1` |
| 高度布局 | `5.1.2 未支持`（仅诊断） | 任何 Atmos/height 可用暗示 |
| 端点不足 | `端点不足，已下混/仅前置` | `完整 5.1/7.1` |

两台 HomePod 的常规状态只允许两种路由措辞：`M_*_2` 的“立体声下混”，或 `M_FRONT_PAIR` 的“仅前置 L/R”。不得出现 Dolby、DTS、Atmos、原生环绕或“影院 5.1 已开启”。

## 6. 视觉与无障碍

- **层级**：源布局 13 pt medium 最高；实际路由 11 pt secondary；端点徽标为 caption 胶囊。警告不抢过启停开关。
- **对比度**：正文 ≥ 4.5:1，大字号/图标 ≥ 3:1；提高对比度模式下橙色仍配图标与文字。深色模式使用系统语义色，不自定义第三套主题。
- **减少动态**：关闭脉冲、波形循环与进度动画，改用静态 `circle.fill` + 状态文字；`ProgressView` 只保留系统不确定进度或静态替代。
- **VoiceOver**：输入摘要合并为一个元素，示例：“输入，5.1 Side，6 声道，播放器输出，原生性未验证。实际路由，5.1 到两台 HomePod 立体声下混，LFE 丢弃。状态，正在路由。”
- 开关标签“系统音频”，提示：“开启后检测输入布局并路由到已保存的音箱；两台 HomePod 不会作为 5.1 环绕端点。”
- 高级信息折叠时提示“高级信息，已折叠”；展开后按行朗读，不把 UID 连成一串。
- 文本放大到 200% 时路由行可换两行，不截断“下混/丢弃”等关键损失词。

## 7. 实现检查清单（仅 gates 通过后）

- [ ] **前置**：L1（7 个容器真实枚举/逐通道 PCM）与 L2（逐布局源报告/夹具）通过；未通过前不写任何 UI。
- [ ] 仅新增只读展示模型，复用 `AppState` 单一状态源；不新增控件、页面、声道选择器、文件播放器或默认上混。
- [ ] 菜单摘要与设置只读卡片共用同一 formatter，文案来自 route plan 的 provenance/losses。
- [ ] 两台 HomePod 强制 `downmix` 或 `front_pair` 标签；用两个端点的快照测试禁止出现“原生 5.1/7.1”。

- [ ] 源布局变化、`hflr` 变化、清理未确认均停止整组，不显示“正在路由”。
- [ ] VoiceOver、200% 文本、减少动态、浅/深模式与对比度检查。
- [ ] 截图仅用于验收实现后的窗口状态，不用效果图代替；不把未来态图放入当前产品。

## 8. 未决与边界

- 5.1 side/back 用户覆盖、影院上混、手动端点位置确认均不在本 UI v1；需要单独产品决定。
- 输入路径（process tap / virtual HAL / player adapter）未定，本文不承诺某一后端可用。
- 当前 UI 冻结；本文不构成工期、可用性或“多声道已支持”的声明。
