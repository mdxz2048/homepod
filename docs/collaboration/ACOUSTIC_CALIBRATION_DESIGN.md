# 无线音频同步：功能与交互设计

日期：2026-11-20。当前为开发设计与静默验证阶段，尚未安装、发布或进行真实音箱声学测试。

## 产品目标与参考

设置页影院模式增加「无线音频同步 / 测试延迟」。测量已保存布局内全部独立音箱，以声音抵达同一听音位置的时间为准保存每台音箱数据。播放时共同延迟上报虚拟声卡，较快音箱获得独立的 PCM 延迟补偿。

视觉参考为用户提供的 `1-1273.mov`（约 29 秒）：深蓝背景、根据音箱方位出现的青/蓝/粉/橙色扁平发光圆环、逐个提示、最终多色光环共同浮现。参考的是空间关系与动画语言；苹果配对过程不等同于声学延迟测量。我们的音箱型号、名称和位置来自已保存布局，不预设实际有四台。

原版约 2000 ms 是协商值（常见 1500 ms）加共同准备缓冲 500 ms，不能当作测量结果。校准主要消除端点与房间到达时间差；不会把 AirPlay 的协议缓冲降到低延迟有线音频水平。

## 完整流程

1. **入口**：设置 → 影院模式 → 无线音频同步。未校准显示「测试延迟…」；已校准显示日期、各音箱延迟/补偿、「重新测试…」「清除校准」。布局有改动先保存；系统播放或更新中禁用开始并说明原因。
2. **准备**：居中标题「让声音，同时抵达。」；音箱按实际房间方位排列。说明 Mac 放在日常听音位置，房间安静，使用内置或 USB 麦克风。固定 5% 音量，仍可能听见；真实开始按钮是唯一的发声触发。设置界面、打开预览、启动应用均不播放。
3. **身份与权限**：发现并用稳定设备 ID 核对全部已绑定音箱，拒绝按旧 IP 给另一台设备套用校准。首次申请麦克风权限；拒绝或缺少任何音箱时提供可操作提示，保持原有校准。
4. **逐台测量**：每次只让一台音箱发声，三次渐入渐出的宽频短测试音。当前音箱对应彩色椭圆光环扩散，其余轮廓降低亮度。显示「正在聆听 客厅 HomePod · 1 / 3」，不要将不确定的网络连接阶段显示成已出声。每次光环对应一次实际测试音，动画不决定测量时间。
5. **分析与重试**：波形互相关识别到达时刻；至少三次通过，再用中位数，保存极差及相关度。5% 听不清、录音过载、时钟中断、回声歧义、结果波动大、端点掉线均不生成成功结果。提示保持安静后重试；不自动提高音量。完整体验应支持单台重试，保留本轮其他可靠结果。
6. **共同复验（设计中）**：临时应用补偿，让各台发送可区分的编码测试信号，在同一录音中分别匹配到达时间。必须使用不同码型，不能从一团相同测试音中猜测每台时间。复验目标为听音位置到达时间极差不超过 10 ms；不满足则提示重试，不显示成功动画。实际阈值需设备实验确认。
7. **结果**：多色光环共同浮现，标题「每一台，都已找到同一拍。」。简洁显示每台实测延迟与需要补的时间；详情显示三次测量、波动、时间、麦克风和共同延迟。以用户点击「保存校准」统一替换旧档案。
8. **生效**：下次开启影院模式重新协商，根据当前协议延迟和所存残差构建计划；先写虚拟声卡并读回验证，再启动采集。写入失败/待处理时不将校准显示为已应用。音乐模式本轮保持原有行为。

## 计算方式

定义每台音箱的协议延迟为 P_i，发送准备预算为 B=500 ms，探测声学残差为 r_i。

- 校准测量时第 i 台名义计划 N_i=P_i+B。麦克风硬件采样时钟与 AirPlay 时间表均映射到同一 Mac 单调时钟；用采样时间而不是麦克风回调到达时间。
- 匹配每次短音实际抵达 A_ij 和对应计划 T_ij，得到 r_ij=A_ij−T_ij。r_i 取三次中位数；展示的实测总延迟 L_i=N_i+r_i。
- 播放时 N=max(P_i)+B，R=max(0,max(r_i))。所有端点的共同名义呈现时刻相同，实际有效延迟为 N+R。
- 第 i 台加 d_i=R−r_i（只允许非负），换算成 44100 Hz 的整帧 PCM 延迟。每台按其协商 P_i 计算独立发送时刻，不能一律假定协议延迟相等。
- 虚拟声卡上报 ceil(N+R) ms，在 0…3000 ms 现有合约内写入并验证。超限明确失败，不截断成一个看起来合法的值。
- 示例：测得 2028/2046/2012/2037 ms，共同目标 2046 ms，分别补 18/0/34/9 ms。交互预览中的这些值只是模拟数据。

Mac 麦克风的输入通道、重采样和 HAL 采集到 Python 之间仍有需要验证的误差。当前探测经与播放相同的 live hub/原生路由/AirPlay 链路，绕过真实虚拟输入采集；不能据此宣称已完整测得虚拟采集/转换延迟。正式音画验收需覆盖真实输入路径，并用支持系统延迟的浏览器/播放器验证口型。声学同步与播放器遵守 HAL 延迟是两个验收条件。

## 保存、取消与恢复

- 保存结构包含版本、设备 UUID/稳定 ID、布局/听音位置、麦克风 UID、每台实测/名义/残差、相关度、三次极差、测量日期。
- 保存全组原子替换；取消或部分失败不覆盖旧结果。开发版当前已有全组成功后显式保存；单台重试与共同复验尚待接入。
- DHCP、重命名或列表排序不使设备身份失效；更换设备、增删音箱、移动音箱或听音位置需要重新校准。
- 麦克风只在用户开始后的测试会话使用；临时录音本机分析，结束/取消后删除，不上传。
- 停止测试立即关闭麦克风，再等待有界的音箱会话清理；退出应用也走同一清理路径。测试不改系统默认输出，不修改日常保存音量。
- 5% 是固定 AirPlay 音量指令，不是无声承诺。睡眠期间的当前开发、预览和软件验证全部静默，不访问麦克风或进行真实发声验收。

## 动画与无障碍

- 深蓝色背景、少量居中文案、没有仪表盘式卡片堆叠。亮点集中在当前音箱与扁平椭圆光环。
- 同一会话内每台保持独立颜色，并配合名称、位置、文字状态；颜色不承担唯一识别职责。
- 准备阶段呼吸亮度；检测阶段三次光环随计划音符扩散、衰减；完成后保留小勾；全组复验完成才同时点亮。
- 设备较多或位置重叠时需散开标签/连线，不能改动真实布局坐标，也不能把名称相互覆盖。
- 尊重减弱动态效果：静态光环及文字进度；VoiceOver 宣告状态切换，不逐动画帧朗读。
