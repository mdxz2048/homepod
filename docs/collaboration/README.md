## 权威文档

| 文档 | 用途 | 唯一维护责任 |
|---|---|---|
| [WORKFLOW.md](WORKFLOW.md) | 角色、交接、并行、集成和验收规则 | 总协调 Agent |
| [TASKS.md](TASKS.md) | 当前里程碑、任务状态、依赖和交付入口 | 总协调 Agent |
| [CONTRACTS.md](CONTRACTS.md) | 接口状态、版本、变更与语义索引 | 技术架构 Agent |
| [ACCEPTANCE.md](ACCEPTANCE.md) | 验收条件、证据及已知缺口 | 验收 Agent |

`PRODUCT.md` 先由总协调根据用户明确目标建立核心库范围，后续由产品角色继续维护。UI Agent 在 UI 阶段创建 `UI.md`；技术架构 Agent 维护 `ARCHITECTURE.md` 和必要的决策记录。

这些文件构成统一文档集。共享入口是本文件，不要求所有 Agent 同时编辑同一个大文件。每份权威文档只有一个维护责任人，其他角色通过任务提案和交接记录提出修改。

## 阅读顺序

每次开始任务，读取本入口 → TASKS 中自己的任务 → 对应产品要求和已批准契约 → 相关决策与最近交接。只在所需范围追溯历史，不依靠聊天记忆推断接口。

## 歧义处理

用户最新明确要求优先。产品要求决定期望行为，批准的接口决定模块间语义，架构决策决定实现约束。发现互相矛盾时暂停受影响部分，由协调与对应负责人收敛并记录；其余无依赖工作继续。不能自行挑选更方便的一份文档执行。

提案必须标记 Draft；批准的变更记录批准角色、变更编号与影响任务。批准权由角色承担，不要求用户逐项确认常规工程决策。
