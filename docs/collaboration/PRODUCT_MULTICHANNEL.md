# 多声道产品行为规范：源优先输入与路由

日期：2026-11-06。Owner：产品设计。状态：产品设计基线 v1（Draft，待总协调确认依赖后进入实现）。

依据：[MULTICHANNEL_CONTRACT.md](virtual-audio/MULTICHANNEL_CONTRACT.md) v1、[MULTICHANNEL_TASK_BRIEF.md](virtual-audio/MULTICHANNEL_TASK_BRIEF.md)、[PRODUCT.md](PRODUCT.md)、[APP_ARCHITECTURE.md](APP_ARCHITECTURE.md)、[PROGRESS.md](PROGRESS.md)、[UI_SPEC.md](../design/ui-handoff-v1/UI_SPEC.md)。

本文只定义**用户可见行为**：流程、状态、文案、声明口径、产品验收。接口 token、矩阵系数、错误码以契约为唯一依据；本文不新增 token、不改系数、不写代码。

## 0. 一句话与用户目标

**虚拟声卡是输入能力层，不是“5.1 声卡”。** 播放器把解码后的 PCM 按源布局（mono / stereo / 3.0 / 4.0 / 5.1 Side / 5.1 Back / 7.1）原样送进来；Flow 按“源布局 + 实际端点布局/数量”选一条可解释的路由，并如实说明它做了什么、丢了什么。

用户实际在做的事：

1. 在自己的播放器（IINA/mpv/VLC/浏览器）里播放，不在 Flow 里选文件。
2. 首次在播放器的音频输出里选一个 `HomePod Flow Audio …` 设备。
3. 在 Flow 里看到：源是什么、端点有几台/什么布局、会怎么路由、有什么损失。
4. 点开始/停止；总音量和音画偏移沿用现有控件。

成功 = 用户一眼知道“现在听的是 5.1 源下混到两台”，不会误以为在听 5.1。失败 = 容器 8ch 就自称 7.1、立体声 passthrough 自称 5.1、两台下混自称原生、静默丢 LFE 不说明。

非目标：不做产品内文件播放器；不做逐通道编辑器/增益矩阵；不做 AC-3/DTS/TrueHD/Atmos 直通或对象音频声明；不做 height 实现；不自动改系统默认输出。

## 1. 术语与模式

三个布局必须分开显示，禁止混用：

| 用户词 | 含义 | 谁能决定 |
|---|---|---|
| 源布局 | 播放器/解码器报告的布局 | 用户换播放器输出或显式覆盖；App 不能改 |
| 容器布局 | 虚拟设备实际通道数+标签 | 用户选哪个设备；App 可按源建议 |
| 端点布局 | 实际 HomePod 的数量+位置组合 | 用户在布局页确认；程序不得猜 |

路由模式（产品词 ↔ 契约 token）：

| 徽标 | token | 含义 | 禁止说法 |
|---|---|---|---|
| 直通 | `native` | 同布局同标签、端点完整 | 端点不完整时称直通 |
| 补位 | `padded` / 捕获 `pad_silent` | 源是子集，多出通道精确静音 | “原生 {更宽布局}” |
| 位置重映射 | `layout_remap` | 5.1 Side↔Back、4.0→5.1S 等 | “原生 5.1 Side/Back” |
| 下混 | `downmix` | 显式矩阵，记录损失 | 只写“5.1”不写下混 |
| 仅前置 | `front_pair` | 只取 FL/FR，其余丢弃 | “立体声下混”（它是丢弃，不是下混） |
| 上混 | `upmix` | 用户显式开启的固定线性矩阵 | “原生/Dolby/DTS/Atmos” |
| 单声道分配 | `mono_map` | M→L=R 或只进 FC | “立体声源” |

声明口径：**“原生”只用于源证据（`源原生`）或完整链路直通；整条链的“原生 5.1/7.1”只在源原生 + 容器同布局 + 端点完整且位置已确认时成立，声学仍需单独标注未验证。** 两台 HomePod 永远不成立。

## 2. 范围

| 类别 | 布局 | 产品状态 | 用户可见 |
|---|---|---|---|
| 基线 | stereo (2) | 设备与链路已有部分真机证据 | 可用；不得据此宣称多声道 |
| R1 | mono (1)、3.0 (3)、4.0 (4)、5.1 Side (6)、5.1 Back (6)、7.1 (8) | 契约冻结，设备/采集/路由待实现与 Gate 1/2 | 未通过前显示“未就绪”，不列入已支持 |
| RES | 5.1.2 (8)、7.1.2 (10)、7.1.4 (12) | 只预留命名 | 不显示为可用；请求即“本版本不支持” |
| 拒绝 | unknown 多声道、5.1 未分 Side/Back、4.0 Side 变体、encoded/Atmos | — | 明确报错，不猜、不静默降级 |

端点：当前只有两台 HomePod → 端点布局 `ST`，只允许立体声下混或仅前置。3.0/4.0/5.1/7.1 端点属于“端点足够以后”的能力，需要 3/4/6/8 个位置确认的端点；height 需要 10/12 个。

当前就绪度（不得对外宣称已支持）：只有 stereo 虚拟设备真机枚举；6/8ch 设备、产品 Input、HPCM v2、多声道路由均未实现；两台 HomePod 的下混路由矩阵已冻结但产品未接。

## 3. 界面约束（正常流程保持最小）

不新增页面、不新增侧栏项、不做第二个布局编辑器：

- **菜单栏弹窗**：现有结构不变，只把副标题变成一行 `输入 {源} · {路由}`（超长截断，详情在设置）。
- **设置 → 空间布局页**：标题下加一条“输入与路由”状态卡：三个 chip（输入设备 / 源布局 / 端点+路由）+ 一行摘要；点击展开详情（同页折叠）。
- **详情面板**：证据链（源/容器/端点）、矩阵 ID、损失、采样率转换、警告、少量高级动作（仅前置、上混开关、诊断）。
- **诊断**：留在“通用设置 → 诊断/日志”，不在主界面暴露矩阵系数。

必须存在的组件：`RouteSummaryLine`、`LayoutChips`、`RouteModeBadge`、`RouteDetailPanel`、`EndpointPositionEditor`（仅端点数≥3）、`CopyDeviceNameButton`、`BlockingStateView`（空态/错误带动作）。

明确禁止：文件播放器/播放列表；逐通道勾选、增益、延迟矩阵；`5.1/7.1 音效`开关；Dolby/DTS/Atmos 商标；把设备数当声道数；用电平/静音推断布局；自动改系统默认输出；用 toast 代替持久错误。

## 4. 主流程

### 4.1 首次运行

| 步骤 | 用户看到 | 失败/分支 |
|---|---|---|
| F1 检测组件 | 未安装空态：用途、需要管理员、可能重启音频服务 | 不显示“已连接” |
| F2 安装 | 设备出现在系统与播放器 | 安装失败 → 重试/诊断 |
| F3 授权 | 未授权空态 + 打开系统设置 | 拒绝 → 只能系统立体声兜底，并明确标注 |
| F4 在播放器选输出 | 给准确设备名 + 复制按钮 + 按内容建议（下方） | 不改播放器设置、不假装知道用户选了什么 |
| F5 等待 PCM | “已就绪，等待播放” | 无 PCM ≠ 无声 ≠ 降级；静音是合法内容 |
| F6 预检 | 源布局、端点、路由摘要、损失、警告 | 不可路由 → 阻断态 + 可用动作 |
| F7 开始 | 正在启动 → 正在播放 | 启动失败 → 不留半启动状态 |
| F8 停止/退出 | 已停止、输出已释放 | 默认输出仍指向虚拟设备 → 提示恢复 |

设备选择建议（帮助文案，不自动改播放器）：单声道选 `HomePod Flow Audio Mono`；立体声选 `HomePod Flow Audio`；5.1 已知 Side/Back 选对应设备；不确定 5.1 环绕位置或 7.1 选 `HomePod Flow Audio 7.1`（可承载 5.1/7.1，多出通道静音）。

### 4.2 自动检测虚拟输入

顺序固定（契约 §2.7 的产品表达）：

1. 先读源布局；无权威布局 → 不自动选多声道设备。
2. 找正在运行的虚拟设备；精确匹配优先。
3. 无精确匹配 → 选最小超集（如 5.1→7.1），标“补位”。
4. stereo 源默认选 stereo 设备；只有播放器已选 5.1/7.1 时才走 passthrough。
5. 绝不选子集容器（7.1→5.1、5.1B→5.1S、4.0→5.1S）。
6. 多个设备同时活动 → 冲突提示，只用一个，不拼接、不切换 header。

手动选择只允许在“已检测到的虚拟设备”之间，且选后仍做布局兼容校验；不提供通道编辑。记住上次选择可以，但不得覆盖用户本次在播放器里的选择，也不得未经确认自动开始。

### 4.3 源布局

源布局 chip 只由 `SourceLayoutDescriptor` 生成：

| 条件 | 必须显示 | 禁止 |
|---|---|---|
| `source_native` + 容器同布局 | `5.1 Side（源原生）` | 源是 5.1 时显示 7.1 |
| `source_padded` | `5.1 Side 源在 7.1 容器（多出通道静音）` | `原生 7.1` |
| `stereo_passthrough_in_multichannel` | `立体声（仅前置 L/R，其余静音）` | `5.1`/`7.1`/`原生多声道` |
| `source_upstream_mapped` / `authority=player_output` | `播放器输出 5.1（原生性未验证）` | `原生 5.1` |
| `unknown_restricted` | `未知多声道，仅前置 L/R` | `5.1`/`7.1` |
| 5.1 未分 Side/Back | `5.1（环绕位置未确认）` | 默认 Side 或 Back |

不得由通道数、静音、设备名、文件名推断布局；布局在 session 内不可变。

### 4.4 端点数量与布局

- 端点 = 一个 AirPlay 输出目标（单台 HomePod，或已配对的 HomePod 立体声对，后者算 1 个端点）。
- 当前两台 = `ST`，每台收到同一 L/R；文案写“2 个端点 · 立体声（每台同声）”，不写“空间环绕”。
- 端点数≥3 时，用户为每台音箱指定位置（`FL FR FC LFE SL SR BL BR` 之一）；组合必须完整匹配 R1 的 3.0/4.0/5.1S/5.1B/7.1 之一，否则：
  - 不完整 → `insufficient_endpoints`（如 4/6，缺中置和 LFE）；
  - 重复/未知 → `endpoint_layout_unconfirmed`；
  - 不匹配任何布局 → `route_unsupported`。
- 现有“前方一台 + 后方两台”的 3 台摆位**不是 3.0**（3.0 需要前左/前右/中置）。R1 视为不可路由，只允许 ST；不得把后方两台当 SL/SR 后称 5.1。
- 位置只能由用户确认；可由已保存坐标“建议”位置，但必须显式确认后才生效。端点掉线/位置变化 → 停止整组，不静默重排。

### 4.5 路由计划（开始前必须可见）

摘要一行：`{源} → {端点摘要} · {模式}`，损失追加在括号里。详情必须包含：矩阵 ID、被合并/丢弃的标签、未使用端点、采样率转换（如 48→44.1 kHz）、端点是否位置确认、声学是否未验证。

默认策略：

- 到两台：默认 `M_*_2` 下混；`M_FRONT_PAIR` 只在详情里作为显式选项（标“其余丢弃”，不是下混）。
- 5.1 Side↔Back：位置重映射，不是原生。
- 立体声上混：默认关闭，每次会话显式开启，标“非原生”。
- 矩阵/session 内不可变；换矩阵必须停止、新 session。

### 4.6 启动

开始按钮可用需同时满足：组件已装、已授权、有 PCM、源布局已知（或用户显式受限覆盖）、容器匹配、端点满足、路由 accepted、无多设备冲突。

点击后“正在启动”，worker ready 后“正在播放 · {摘要}”；失败给持久错误 + 下一步，不保留半启动。默认不自动开始。

### 4.7 播放中变化

以下任一情况必须**停止整组**并提示，不自动恢复、不热切换：源布局变化；容器变化；端点增删/位置变化；影院/同步模式切换；`hflr` 变化；输入断流/不连续；权限被撤销。

### 4.8 停止

停止 → 清队列、释放输出、旧 session 失效 → “已停止 · 输出已释放”。停止幂等，启动中也可停止。若系统默认输出仍指向虚拟设备，提示“系统输出仍指向 HomePod Flow Audio”并给“打开声音设置”；不静默留默认。

### 4.9 不支持 / 歧义

| 情况 | 文案 | 允许动作 |
|---|---|---|
| 5.1 未分 Side/Back | `5.1（环绕位置未确认）` | 显式“按 Side/按 Back”；覆盖后标未验证、不可称原生 |
| unknown 多声道 | `无法识别源布局` | 仅前置 L/R（显式、受限）或改用 stereo 设备 |
| 7.1 源进 6ch 容器 | `源通道多于容器，不能在此设备降混` | 改用 `HomePod Flow Audio 7.1` |
| 5.1 Side 源进 5.1 Back 设备 | `源布局与所选设备不匹配` | 改用对应 Side/Back 或 7.1 |
| 4.0 Side 变体 | `无法识别 4.0 的环绕位置` | 7.1 容器或调整播放器 |
| height | `本版本不支持 5.1.2 / 7.1.2 / 7.1.4` | 无；不显示为可用 |
| 播放器直通压缩码流 | `播放器可能开启了音频直通，请改为解码 PCM` | 调整播放器 |
| 采集只得到立体声 | `当前采集路径未保留多声道，已按立体声处理` | 诊断；不得称 5.1 |

### 4.10 两台 HomePod 的限制

固定提示（预检即出现，不等播放后）：

> 两台 HomePod 只能立体声下混或仅前置，不能还原 5.1/7.1 的方向。

允许：`M_*_2` 下混、`M_FRONT_PAIR`。禁止：任何 native 5.1/7.1、把 6/8ch 直接送两台后称多声道、“两台组成 5.1”。影院模式不改变这个事实；它只在端点足够时按位置分配。

### 4.11 更多端点以后

添加端点 → 指定位置 → 完整性校验 → 预览路由变化 → **停止并重新开始**（新 session）。升级文案如“现在可以 5.1 直通（6 端点，位置已确认）”；降级文案如“端点不足，已改为立体声下混”。端点足够 ≠ 声学通过：详情固定标“声学方向未验证”，直到 Gate 3 证据。LFE 端点必须显式指定，并标“低频能力未验证”，不得默认称完整 5.1。

### 5.1 禁止声明（硬规则）

1. 立体声 passthrough 不得称 `5.1`、`7.1`、`原生多声道`。
2. 两台 HomePod 下混不得称 `原生 5.1/7.1`，也不得只写 `5.1`/`7.1` 而不写“下混/仅前置”。
3. 7.1→5.1 下混不得称 `原生 5.1`；Side↔Back 不得称 `原生 5.1 Back/Side`。
4. 8ch 容器不得推断为 7.1；6ch 未分 Side/Back 不得默认。
5. `player_output` 不得称 `原生`；未通过 Gate 2 的布局不得称“支持”。
6. 上混不得出现 `Dolby`、`DTS`、`Atmos`、`杜比`、`全景声`、`原生`。
7. 不得出现 `真 5.1`、`无损多声道`、`影院级环绕`、`零延迟`、`已解锁 5.1`（除非有对应证据）。

开放问题（括号内为当前默认）：

1. device tap 是否保留 6/8ch？未通过则整个多声道产品不可用，不做替代宣称。
2. 哪些播放器能报告源布局？浏览器只给 stereo 时显示“播放器输出 立体声（可能已降混）”（不接受把它当 5.1）。

4. 现有“前中+后左+后右”三台摆位如何呈现？（默认：不属于 3.0，只允许 ST，并解释 3.0 需要 FL/FR/FC。）
5. 同步模式在 >2 端点时是否所有端点同一下混？（默认：是；不产生多声道 native。）
6. 端点位置确认交互？（默认：列表选择 + 坐标建议 + 显式确认，不允许自动套用。）
7. 5.1 Side/Back 覆盖是否记住？（默认：仅本次会话，不跨会话记忆。）
8. 上混是否长期记住？（默认：默认关闭，每次会话显式开启。）
9. LFE 端点如何指定与验证？（默认：用户显式指定，标“低频未验证”，不称完整 5.1。）
10. 7 个设备名是否让用户困惑？（默认：不改名，用首次帮助和按内容建议缓解。）
11. 48k→44.1k 是否在主界面显示？（默认：详情显示，不当作错误。）
12. height 是否显示“即将支持”？（默认：不显示，只解释不支持。）
