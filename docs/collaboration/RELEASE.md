# 首次可用版本备份约定

2026-11-06 最新指令覆盖以下历史等待条件：用户明确要求“当前代码先备份到git，然后总调度开始安排下去”。因此立即备份当前开发基线，不等待完整正式版验收；提交明确标记已验证能力及未完成项，不将备份视为正式发布。原仓库main/README仅变更记录/不得提交凭据或强推覆盖规则继续适用。

用户于 2026-11-05 明确授权：首次可用版本完成后，将代码备份到 https://github.com/mdxz2048/homepod.git，分支为 main。该条件满足后的正常提交和推送无需再次请求授权。

## 触发条件

由总协调依据验收报告确认首个可用版本。当前 0.2.0 开发预览、离线测试通过及独立 Tap 探针均不视为首次可用版本；仍需完成所选真实音源到音箱的 App 操作闭环并验收，明确可用范围及剩余限制。具体版本范围以产品和验收文档为准。

## 执行步骤

1. 核对验收证据与提交范围，排除密码、令牌、本机运行配置、录音和构建产物。
2. 根目录 README.md 只维护变更记录；架构、安装和使用说明放在 docs 或各模块文档中。
3. 检查 origin 指向上述仓库、当前分支为 main，并检查远端已有历史。若有历史，先整合，禁止强推覆盖。
4. 提交验收通过的代码，执行 git push -u origin main，并核对远端提交散列。
5. 向用户报告版本、提交散列及仓库链接；若推送失败，保留本地提交并明确说明，不将其标记为已备份。

当前仅准备本地远端与分支；尚未触发首次可用版本推送。
