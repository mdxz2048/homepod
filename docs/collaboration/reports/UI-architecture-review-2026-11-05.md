# UI 交接包产品与架构审核

日期：2026-11-05。审核角色：产品／技术架构。已读取 UI_SPEC.md、AGENTS.reference.md、ACCEPTANCE.md，并逐张查看三张 PNG；reference 文档作为交接资料，不作为自动执行或覆盖用户指令的规则。

结论：可按参考实现菜单栏 App 和唯一设置窗口，首版先明确标记「界面演示」。独立服务承接真实能力，核心 C ABI v1 保持不变；目前不能把整张设计的功能都解释成后端已完成。

## 功能对应与真实边界

| 设计功能 | 当前能力／首版处理 |
|---|---|
| 菜单栏、双模式、设置、共享布局、拖拽与保存 | 可完整实现原生 UI，菜单小图和大图共享 RoomLayout/RoomCanvas；布局草稿与已保存布局分开 |
| 开启／设备已连接 | 真实状态只能由服务事件给出；Demo 显示「演示 · 3 台示例设备」，不能用普通「3 台设备已连接」冒充发现结果 |
| 多路同步 | 核心支持不同内容和共同计划；M1 两台实际出声及短时主观同步，M2 两台一分钟发送与有界流执行有证据。三台本轮、量化声学误差与长期漂移未完成；M2 独立终审待补 |
| 影院模式 | 核心现有能力是通道复制，没有自动捕获5.1、5.1混音矩阵或批准的立体声空间算法。不能因切换模式就宣称真实环绕；不可拆分时明确同声退化及实际生效模式 |
| 同步播放 | 可在服务层为所有输出设置同一输入通道／同一立体声映射；UI 中布局保留但编辑禁用 |
| 总音量 | 现有会话支持启动音量设定；实时滑动调整尚需服务接入与事件确认，不能只改百分比便标已应用。保存用户偏好，不自动恢复历史100%并出声 |
| ±3500ms音画偏移 | 保留范围、输入校验和偏好值；当前无视频控制或统一音画补偿，Demo明确「仅演示，未应用」，真实模式禁用或返回不支持。负值不能假装把捕获后的声音提前 |
| 双mini立体声对 | 当前正式后端不支持。支持分开的独立mini；已配对组应标不支持并禁止启动，不能偷偷拆成两个AirPlay输出。未来一组两通道、两处空间位置的模型可预留 |
| 添加设备／测试声音／自动处理／低延迟 | 演示添加只能是示例；真实添加由发现服务；声音测试须用户显式点击并报告结果。未实现的处理／低延迟选项禁用并说明，不做假开关 |

系统／应用捕获、权限接管与文件测试播放是不同能力。首版启停不得把测试音频播放写成「已接管系统声音」。参考中的距离米数不来自归一化坐标，未经校准不要伪造2.3m等数据。

## App 层边界与建议文件归属

建议应用目录 `apps/macos/HomePodFlow/`；新建应用接口不改动冻结核心符号。

| 文件区域 | 所属与职责 |
|---|---|
| `Models/` | App开发：RoomLayout（0...1坐标）、设备与输出组、模式、连接状态、能力与requested/applied值 |
| `Services/RouterService.swift` | App开发：独立异步服务协议；start/stop、发现、音量、保存布局、偏移请求与事件流。结果明确applied/unsupported/failed，不能用Bool混淆 |
| `Services/DemoRouterService.swift` | App开发：显式Demo数据与可预测状态；不打开音箱、不读取伪造设备状态 |
| `Services/WorkerRouterService.swift` | 后续App／底层协作：受管独立进程、命令ID/会话generation、事件及退出清理；Python私有补丁不得运行在SwiftUI进程 |
| `State/AppStore.swift` | App开发：MainActor单一状态源，消费服务事件；启停处理中避免重复请求，旧generation事件不得覆盖新状态 |
| `Views/`、`StyleTokens.swift` | UI开发：菜单弹窗、设置页、共用画布、选择／拖拽／无障碍；不直接调用C函数或启动Python |
| `Persistence/` | App开发：版本化模式/音量/偏移/布局偏好，不持久化「已连接／正在播放」等瞬时真值 |
| `core/`、`bindings/`、`adapters/` | 底层：v1 ABI及真实传输；通过服务边界接入，不由视图改核心 |

布局「应用」先校验再提交；后端未实现摆位到声道算法时只能报告布局已保存，不能声称声音已随拖动变化。运行中重配置未支持时采用显式停止后重建会话，禁止静默修改时间线。首版可保存位置、确认前／左后／右后角色，不承诺连续坐标自动产生距离校正或空间算法。

## 视觉和验收决策

参考核心是浅色系统材质、蓝色双模式、紧凑菜单弹窗与独立设置。可用矢量房间和清楚的前后位置替代P2家具纹理，必须保留可辨耳朵、HomePod:mini约1.45直径比和设备选中联动，不直接贴参考图。应用名按已选HomePod Flow；参考HomePod Spatial是旧示例文案。

本轮验收分开：原生build与A-G运行截图／交互检查；Demo明确标记且无音箱动作；真实服务连接另行验收。立体声对条目先记「不支持，未验收」，不得为了勾选整表伪造能力。所有真实状态、实际音量和偏移生效均需服务反馈证据。

冻结门禁继续执行 docs/api/v1：头hash、9符号／错误码／回调与生命周期、旧已编译客户端只换新库的兼容测试。UI开发无需重开核心API设计；服务层先稳定产品状态，后续逐步替换Demo为真实实现。
