# HomePod Flow：当前阶段产品范围

日期：2026-11-05。早期按用户要求核心优先；接口冻结及两设备短时链路验证后，用户最新提供UI交接包，明确要求总协调评估、分配并开始开发界面。当前并行实施UI演示切片，核心未完成的验收继续保留，不能因UI完成而标记核心全面通过。

## M0：可运行的无界面核心基础

| 需求 ID | 行为 | 验证层次 |
|---|---|---|
| CORE-001 | 支持 N 个独立输出，不固定三台、不固定地址 | 离线接口/行为测试 |
| CORE-002 | 不同输出可以得到不同音频内容，并映射到同一媒体时间 | 路由和计划记录；真实出声后续 |
| CORE-003 | 统一启动计划，显式校验后端是否能执行定时语义 | 模拟时钟/传输测试 |
| CORE-004 | 正常启停、部分准备失败、背压及非法输入有明确行为和清理 | 独立异常路径测试 |
| CORE-005 | 核心不依赖 SwiftUI、Mac 捕获、固定IP或协议库对象 | 构建与架构审核 |
| CORE-006 | 保留现有成功 Python AirPlay 原型及证据，不能以模拟冒充真机 | 内容哈希与非播放回归检查 |

M0 是后续真实核心链路的基础，不等于所有核心功能完成。允许使用明确的模拟接收端；禁止自动触发音箱播放。

## M1：真实 AirPlay 集成

原有 ALAC 与 AirPlay 会话适配到正式核心调用链，实际设备验证三台不同内容、重复启停、失败清理；完成录音定量和长时间同步证据。不能以发送日志代替实际出声。

## M2：持续实时核心

持续音频块输入、时间戳变化、跳转/新世代、断线重新加入和恢复，完成所需漂移策略与长时验收。达标后再进入 Mac 捕获与 UI 产品化。

### 当前切片 M2-A：接口冻结与有界持续流

用户明确要求先固定核心接口。现有公开C ABI v1和C++源码接口保持不变，调用约定、错误码、所有权与状态语义纳入兼容性门禁。跨平台/App依赖C ABI；C++不承诺不同编译器的二进制兼容。

通过现有submit按块处理输入，逐块输出到有界缓冲，验证60秒或更长的逻辑流不会随时长线性缓存全部音频。使用可控输入与已授权两台设备，不引入UI、系统捕获、自动重连或漂移校正承诺。旧play/dry-run及既有测试继续可用；旧编译C客户端应可加载新库。

有声测试默认15%；历史100%仅用于用户明确指定的10秒测试，不作为自动恢复默认值。较长真机运行先以一分钟及短重复启动作为当前阶段验证，不以此宣布小时级稳定或精密声学通过。

其他平台首期目标是核心可移植；Windows/Linux 的系统声音捕获和界面不在本轮范围。原生立体声对继续列为未验证，不默认启用。
